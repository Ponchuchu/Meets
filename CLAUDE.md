# рядом. — правила для Claude Code

Ты строишь настоящее мобильное приложение «рядом.» по готовому макету: карта событий и афиша Алматы, свайпы «Для тебя», друзья на карте, «ищу компанию», чаты, профиль с картой города. Владелец — Данил, он не программист, пишет по-русски и хочет получить приложение целиком. Всё решено и описано в `docs/`: тебе нужно не придумывать продукт заново, а аккуратно собрать его.

## Что читать перед работой

1. `docs/ROADMAP.md` — этапы с галочками. Бери первый незакрытый этап.
2. `docs/PRODUCT.md` — как всё работает: вкладки, жесты, правила, приватность.
3. `docs/SCREENS.md` — какой экран в каком файле макета.
4. `docs/DESIGN.md` — цвета, шрифты, размеры, анимации.
5. `docs/TECH.md` — стек, сервисы и API, модель данных, ключи.
6. По этапу: `docs/RECOMMENDATIONS.md` (лента «Для тебя») и `docs/PIPELINE.md` (сбор событий и админка).

Для каждого экрана, который делаешь, открой картинку `design/png/<Экран>.png` (так он должен выглядеть) и исходник `design/screens/<Экран>.dc.html` (точные отступы, цвета, тексты, логика состояний в `<script>` внизу файла). Как читать исходники — в `design/README.md`.

**Что главнее, если источники расходятся:** `docs/*.md` → `design/png` → `design/screens`. В документах самые свежие решения.

## Как работать

- **Этап за этапом.** Коротко спланируй этап, сделай, проверь, закоммить, отметь галочку в `docs/ROADMAP.md` с короткой заметкой, запушь. Не перескакивай вперёд и не переделывай готовое без причины.
- **Демо-режим с первого дня.** Приложение обязано запускаться и работать без единого ключа. Все данные идут через слой `src/data/` с одним интерфейсом и двумя реализациями:
  - `demo` — данные из макета: события, друзья, чаты, фото из `design/assets`;
  - `supabase` — включается, когда заданы переменные окружения.

  Нет ключа — не блокируйся. Делай демо-реализацию и допиши в `docs/KEYS.md`, что нужно от владельца.
- **Проверяй глазами.** После каждого экрана собери web-версию и сними скриншот 390×844 через Playwright (Chromium уже установлен). Сравни с `design/png`. Скриншоты готовых экранов клади в `docs/progress/<этап>/`: так владелец видит результат прямо на GitHub с телефона.
- **Проверки перед коммитом:** `tsc --noEmit`, линтер и тесты логики (свайпы, рекомендации, правила видимости) должны проходить.
- **Коммиты** маленькие и понятные. Пушь после каждого этапа. Если среда держит тебя в отдельной ветке, после этапа открой PR в `main` и одной строкой напиши владельцу, что нажать.
- **Экономь бюджет.** У владельца ограниченный кредит:
  - не устраивай долгих исследований — основные решения уже в `docs/TECH.md`;
  - не перечитывай большие файлы без нужды;
  - не переписывай работающий код ради красоты.

  Сомневаешься в версии библиотеки — одна проверка в документации, и дальше.

## Правила качества

- Тексты интерфейса — по-русски и дословно как в макете, обращение на «ты». Никаких эмодзи вместо иконок: только линейные иконки (lucide) толщиной ~1.8, как в макете.
- Экраны должны быть максимально близки к `design/png` на 390×844: шрифты Geologica, Golos Text и JetBrains Mono, палитра и радиусы из `docs/DESIGN.md`.
- Анимации из `docs/DESIGN.md` обязательны, особенно свайп, улёт карточки в профиль, «+1» на вкладке и шторки. Это ядро ощущения от продукта.
- Кнопки не меньше 44 pt. `accessibilityLabel` у иконок-кнопок. Контраст текста не ниже 4.5:1.
- Приватность из `docs/PRODUCT.md` («Кто что видит») не нарушать ни в коде, ни в демо-данных. Механика рекомендаций пользователю не показывается нигде: она видна только команде в админке.

## Секреты

Ключи никогда не коммить. Держи `.env.example` с именами переменных. Настоящие значения владелец кладёт:

- в переменные окружения облачной среды Claude Code;
- в секреты GitHub Actions;
- в EAS secrets;
- в секреты Supabase.

Инструкцию «что где взять» веди в `docs/KEYS.md` простым языком: владелец не разработчик.

## Как отчитываться

В конце этапа напиши владельцу 3–5 коротких строк по-русски:
- что теперь работает;
- где посмотреть (скриншоты в `docs/progress/…` или ссылка на превью);
- что нужно от него (ключ, аккаунт, решение), если нужно.

Без технических подробностей, если он сам не спросит.
