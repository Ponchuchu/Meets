# рядом. — правила для Claude Code

Ты строишь настоящее мобильное приложение «рядом.» по готовому макету: карта событий и афиша Алматы, свайпы «Для тебя», друзья на карте, «ищу компанию», чаты, профиль с картой города. Владелец — Данил, он не программист, пишет по-русски и хочет получить приложение целиком. Всё решено и описано в `docs/`: тебе нужно не придумывать продукт заново, а аккуратно собрать его.

## Что читать перед работой

0. **`docs/FIX3.md` — сейчас самое главное (20 октября): исправления после APK 20 октября, этапы Ф0–Ф13.** Затем `docs/FIX1.md`.
   **`docs/FIX1.md` (5 октября, вечер): исправления после проверки на телефоне, этапы И0–И7.** Потом — `docs/ALPHA.md` с А4.
   **`docs/ALPHA.md` (5 октября): альфа v6 на двух Android-телефонах, настоящая база без демо.** Порядок: этап 14 из `ROADMAP.md`, потом А0–А9 из `ALPHA.md`.
1. `docs/ROADMAP.md` — этапы с галочками. Бери первый незакрытый этап.
2. `docs/PRODUCT.md` — как всё работает: вкладки, жесты, правила, приватность.
3. `docs/SCREENS.md` — какой экран в каком файле макета.
4. `docs/DESIGN.md` — цвета, шрифты, размеры, анимации.
5. `docs/TECH.md` — стек, сервисы и API, модель данных, ключи.
6. По этапу: `docs/RECOMMENDATIONS.md` (лента «Для тебя») и `docs/PIPELINE.md` (сбор событий и админка).
7. **`docs/V6.md`** — **главный документ (4 октября): финальный макет v6 и полное ТЗ** — каждый экран, нажатие, жест, состояние, данные, панель разработчика, иконка (этапы 23–32). **`docs/V4.md`** (2 октября, частично отменён v6 — см. `V6.md` §0): друзья вместе, правила «без глюков». **`docs/V3.md`** — вкладки, экраны, запросы, огоньки, уведомления. **`docs/V2.md`** — список ошибок (этап 14). Где они расходятся с `PRODUCT.md`, прав `V6.md`, потом `V4.md`, `V3.md`, `V2.md`.

Для каждого экрана, который делаешь, открой картинку `design/png/<Экран>.png` (так он должен выглядеть) и исходник `design/screens/<Экран>.dc.html` (точные отступы, цвета, тексты, логика состояний в `<script>` внизу файла). Как читать исходники — в `design/README.md`.

**Что главнее, если источники расходятся:** `docs/V6.md` → `docs/V4.md` → `docs/V3.md` → `docs/V2.md` → остальные `docs/*.md` → `design/png` (экраны `V6*` главнее `V5*`, `V5*` главнее `V4*` и так далее) → `design/screens`. В документах самые свежие решения. Действует v6: вкладки Карта · Рекомендации · Планы · Чаты · Профиль **только иконками**, карта на ближайшие 24 часа, дата — в фильтрах, незнакомым — только запросом, все приглашения — в «Планах» и в чате одновременно.

## Как работать

- **Этап за этапом.** Коротко спланируй этап, сделай, проверь, закоммить, отметь галочку в `docs/ROADMAP.md` с короткой заметкой, запушь. Не перескакивай вперёд и не переделывай готовое без причины.
- **Альфа — без демо** (`docs/ALPHA.md` §0): сборка для телефонов работает только с настоящей базой (`EXPO_PUBLIC_DATA_MODE=live`), демо-данные — только для тестов и web-скриншотов. Номера и коды тестеров не коммитить: они только в секрете Supabase `ALPHA_TESTERS`.
- **Демо-режим** (для тестов и скриншотов). Приложение обязано запускаться даже без сети и ключей. Все данные идут через слой `src/data/` с одним интерфейсом и двумя реализациями:
  - `demo` — данные из макета (друзья, чаты, фото из `design/assets`) плюс настоящие события из `data/seed/events-almaty.json`;
  - `supabase` — основная. Проект уже создан, публичные ключи лежат в `config/public-keys.json`. Если Supabase недоступен, приложение само переключается на `demo`.

  Нет ключа или доступа — не блокируйся. Делай демо-реализацию и допиши в `docs/KEYS.md`, что нужно от владельца.
- **Проверяй глазами.** После каждого экрана собери web-версию и сними скриншот 390×844 через Playwright (Chromium уже установлен). Сравни с `design/png`. Скриншоты готовых экранов клади в `docs/progress/<этап>/`: так владелец видит результат прямо на GitHub с телефона.
- **Проверки перед коммитом:** `tsc --noEmit`, линтер и тесты логики (свайпы, рекомендации, правила видимости) должны проходить.
- **APK собирать только по просьбе владельца.** Закончил работу — закоммить и запушь, но процесс «Android APK» сам не запускай (решение Данила, 21 октября). Бесплатные сборки Expo ограничены; без лимита — `builder: github` в том же процессе.
- **Коммиты** маленькие и понятные. Пушь после каждого этапа. Если среда держит тебя в отдельной ветке, после этапа открой PR в `main` и одной строкой напиши владельцу, что нажать.
- **Экономь бюджет.** У владельца ограниченный кредит:
  - не устраивай долгих исследований — основные решения уже в `docs/TECH.md`;
  - не перечитывай большие файлы без нужды;
  - не переписывай работающий код ради красоты.

  Сомневаешься в версии библиотеки — одна проверка в документации, и дальше.

## Правила качества

- Тексты интерфейса — по-русски и дословно как в макете, обращение на «ты». Никаких эмодзи вместо иконок: только линейные иконки (lucide) толщиной ~1.8, как в макете.
- Экраны должны быть максимально близки к `design/png` на 390×844: шрифты Geologica, Golos Text и JetBrains Mono, палитра и радиусы из `docs/DESIGN.md`.
- Анимации из `docs/DESIGN.md` обязательны, особенно свайп, улёт карточки в профиль, «+1» на вкладке и шторки. Это ядро ощущения от продукта.
- Кнопки не меньше 44 pt. `accessibilityLabel` у иконок-кнопок. Контраст текста не ниже 4.5:1.
- Приватность из `docs/PRODUCT.md` («Кто что видит») не нарушать ни в коде, ни в демо-данных. Механика рекомендаций пользователю не показывается нигде: она видна только команде в админке.

## Секреты

**Публичные ключи уже в репозитории** — `config/public-keys.json`: токен Mapbox (`pk.…`), адрес Supabase и publishable key. Бери их оттуда.

Секретные ключи никогда не коммить: `sb_secret_…`, пароль БД, personal access token, ключ Anthropic. Держи `.env.example` с именами переменных. Настоящие значения владелец кладёт:

- в переменные окружения или API credentials облачной среды Claude Code;
- в секреты GitHub Actions;
- в EAS secrets;
- в секреты Supabase.

**Таблицы в Supabase** создавай через Management API: `POST https://api.supabase.com/v1/projects/<ref>/database/query` с телом `{"query": "…SQL…"}`. Токен добавляет прокси среды, если владелец настроил API credential (см. `docs/KEYS.md`). Сам токен ты не видишь и не ищешь.
- Миграции храни в `supabase/migrations/`.
- Если запрос не проходит (401/403 или нет сети), не блокируйся: работай в демо-режиме и одной строкой попроси владельца выполнить шаги из `docs/KEYS.md`.

Инструкцию «что где взять» веди в `docs/KEYS.md` простым языком: владелец не разработчик.

## Как отчитываться

В конце этапа напиши владельцу 3–5 коротких строк по-русски:
- что теперь работает;
- где посмотреть (скриншоты в `docs/progress/…` или ссылка на превью);
- что нужно от него (ключ, аккаунт, решение), если нужно.

Без технических подробностей, если он сам не спросит.
