## Находки

1. **Удалённая долгая выставка может вернуться из поиска.** `worker/src/db.ts:43`.

   Вход: сегодня 12 октября; выставка началась 1 октября, заканчивается 30 октября, сотрудник удалил её; другой сайт отдаёт её заново. `known()` берёт только начавшееся после 10 октября и не видит удалённую запись. Воспроизведение: список известных пуст, `processPosts()` возвращает `draft`, то есть новый черновик. То же ограничение позволяет создавать дубли действующих долгих выставок и терять защиту исходного названия после переименования. Исправление: учитывать пересечение периода события с текущим окном, хранить запреты повторного добавления независимо от даты начала; читать весь результат по страницам, а не полагаться на один запрос с `limit=3000`.

2. **«Удалить» и «Снять с карты» убирают событие из планов участников.** `supabase/migrations/20261012000022_admin_events_manage.sql:24` (также строка 22); цепочка: `src/live/api.ts:292` → `supabase/migrations/20261005000014_events_live.sql:11` → `src/features/plans/PlansScreen.tsx:88`.

   Вход: человек записался на будущий концерт, сотрудник удаляет его или снимает с карты. Статус становится `archived` или `draft`. И основной список, и дополнительная загрузка планов читают `events_live`, где разрешён только `published`. После обновления списка концерт исчезнет из «Планов», хотя подтверждение удаления обещает сохранить планы и чаты. Локальная база: запись концерта остаётся, запрос через `events_live` возвращает пустой список. Исправление: отдельная загрузка событий для участников с сохранением проверки доступа, показ отметки «снято/удалено». Физическое сохранение строки само по себе этого не обеспечивает. Удаление самого чата здесь не утверждается.

3. **Адрес без найденного дома получает ложную «точную» точку.** `worker/src/venues.ts:97`.

   Вход: «ул. Абая, 999, Алматы»; сервис не нашёл дом, но нашёл улицу. Повторный запрос удаляет номер дома, принимает произвольную точку улицы и прекращает дальнейший поиск. Воспроизведение: запросы `999 Абая` → `Абая`, результат — координаты улицы. `buildDraft()` принимает эту точку без пометки `needs_pin`; человек может строить маршрут к другому месту. Исправление: результат уровня улицы считать приблизительным, требовать подтверждения точки; сначала проверять адрес с домом через второй сервис.

4. **Сотрудник может переименовать частную встречу через новую функцию.** `supabase/migrations/20261012000022_admin_events_manage.sql:12`.

   Вход: сотрудник вызывает `staff_rename_event` с id события `visibility='friends'`. Проверка сотрудника есть, ограничения публичных событий нет. Локальное выполнение настоящего текста функции изменило название частной встречи. Обычный пользователь получил `staff-only`: это не получение прав сотрудника обычным аккаунтом. Исправление: добавить `visibility='public'` и возвращать понятную ошибку, если подходящей записи нет.

5. **Автоматическая чистка удаляет ещё идущие черновики.** `worker/src/db.ts:92`.

   Вход: сейчас 10:00, событие началось в 09:00, `ends_at=null`, статус `draft`; запускается любой сборщик. Чистка выполняет физическое удаление сразу после начала. При этом `isReliable`, `processPosts`, сводка и приложение дают такому событию ещё три часа. Проверка через `createDb().purgeExpiredDrafts()` с локальной базой действительно удалила одну такую запись. Исправление: одинаковое правило окончания `coalesce(ends_at, starts_at + interval '3 hours')`; сохранять отметку об отбрасывании вместо физического удаления, если она нужна для защиты от повторного поиска.

6. **Подписка на положение может остаться после ухода с карты.** `src/features/map/MapScreen.tsx:179`.

   Вход: экран закрывается, пока `watchPositionAsync()` ещё создаёт подписку. Очистка видит `sub=null`; после завершения ожидания подписка сохраняется, но остановить её уже некому. Воспроизведение с настоящим телом эффекта и задержанным ответом: `remove()` вызван 0 раз вместо 1. Кроме того, переключение вкладок не останавливает этот эффект: он зависит только от `ensureGeo`, а не от `focused`. Исправление: после получения подписки сразу удалять её при `cancelled`; создавать её только при открытой вкладке и повторно проверять отмену после ожиданий. Фоновая передача положения — отдельная существующая функция.

7. **Режим «Оба» теряет результат сайтов, если ключа ИИ нет.** `worker/src/search.ts:430`.

   Вход: режим `all`, Sxodim дал настоящее событие, ключ Gemini отсутствует. После успешного чтения сайта код бросает исключение; файл поиска не получает готовый список, шаг сохранения не выполняется. Воспроизведение: `sources=[{name:'Sxodim',found:1,ok:true}]`, затем `Нет GEMINI_API_KEY`. Обработка отказавшего ИИ ниже сохраняет сайты, но отсутствие ключа обходит её. Исправление: записывать ошибку ИИ в итог и возвращать найденное сайтами; полностью останавливать поиск, только если другого результата нет.

8. **В «Все события» нет действующих долгих выставок.** `src/admin/ui/EventsList.tsx:25`.

   Вход: опубликованная выставка 1–30 октября; сегодня 12 октября. Список требует начало после 10 октября, поэтому выставку нельзя открыть здесь, переименовать, заменить её фото или удалить, хотя приложение показывает её и сводка считает действующей. Исправление: выбирать не закончившиеся события по времени окончания с запасом для событий без `ends_at`, включать `ends_at` в запрос. Случай подтверждён условиями запроса и правилами выборки приложения.

9. **Новое фото не появляется после ошибки старого.** `src/ui/EventCover.tsx:24`.

   Вход: старая обложка не открылась, сработал `onError`; сотрудник заменил её на рабочую, карточка осталась открытой. `broken=true` сохраняется при изменении `cover`, поэтому новый адрес даже не загружается. Проверка настоящего компонента с заменёнными средствами рисования: после обновления адреса элементов `Image` — 0 вместо 1. Исправление: хранить адрес сломанного фото и сравнивать его с текущим, либо сбрасывать состояние при изменении адреса.

10. **Запуск до входа зря ждёт карту и растягивается до 5,75 секунды.** `src/features/auth/Splash.tsx:88` (завершение — строка 85).

    Вход: холодный запуск без входа, открывается приветствие; `MapScreen` не смонтирован, `mapReady=false`, уменьшение движения выключено. Слово уже написано, но раскрытие ждёт предельные 4500 мс; завершение наступает ещё через 1250 мс. Выполнение настоящего тела эффекта с управляемыми часами: `settle=5200`, `end=5750`; сверху может добавиться исчезновение слоя. В `docs/V6.md` предел — 3,4 секунды. Исправление: ждать готовность карты только при переходе к карте; до входа завершать короткую заставку без ожидания несуществующего экрана. Плавность на Android этим воспроизведением не подтверждается.

Действия снять/удалить ограничены публичными событиями, переименование — нет. Обычный аккаунт не может писать/заменять `covers` по проверенным политикам; локальная попытка вставки отклонена. `avatars` уже был публичным, а фото профиля по `PRODUCT.md` видно всем: новая политика чтения сама по себе не раскрывает закрытые фото. Проверка роли и записи выполнена в локальном PostgreSQL (PGlite) с упрощёнными таблицами; настройки настоящего Supabase не проверялись под сотрудником.

В режиме «Скрипт» интерфейс не проверяет модель, но сервер проверяет передаваемую модель; при испорченной сохранённой настройке возможен отказ запуска. Это дополнительное ограничение, а не отдельная подтверждённая находка штатного сценария.
