# Рекомендации «Для тебя»

> Этот документ только для команды. Пользователь механику не видит нигде: ни в интерфейсе, ни в текстах, ни в настройках. Для него подборка просто «угадывает». Смотреть и править вкус может только команда, в админке (макет `TasteAdmin`).

Картинки: `design/png/Recs.png`, `design/png/TasteAdmin.png`.

## Идея

Как в Tinder: лента **бесконечная**, каждый свайп **сразу** меняет следующие карточки.

- **Старт** — ответы при регистрации: что вытаскивает из дома, когда, с кем, бюджет.
- **Дальше** решает поведение. Сильнее всего учит то, что человек сделал в жизни (пришёл, позвал, искал компанию). Свайп — только намерение.

## 1. Сигналы и их вес

| Сигнал | Вес |
|---|---|
| Пришёл («Я на месте» на событии) | +3.0 |
| Ищу компанию | +1.5 |
| Пойду (свайп вправо, «Я иду») · позвал друга | +1.0 |
| Сохранить (закладка) | +0.6 |
| Открыл подробности | +0.3 |
| Смотрел карточку дольше 6 с | +0.2 |
| Мимо после подробностей | −0.2 |
| Пойду, но не пришёл | −0.3 |
| Мимо сразу | −0.4 |
| Отменил за 5 с («Вернуть» / «Отменить») | 0 — сигнал стирается целиком |

- **Затухание.** Свежее важнее: полураспад 30 дней, через 30 дней сигнал весит вдвое меньше.
- **«Мимо» мягкое.** Одно «мимо» почти ничего не меняет. Тема заметно проседает только после **3 «мимо» подряд** в одной категории.

## 2. Из чего состоит вкус

| Часть | Что хранится |
|---|---|
| Темы и теги | Веса ~60 тегов: не «музыка вообще», а джаз, open-air, бесплатно, камерно |
| Время | Сетка 7 дней × утро / день / вечер — когда человек реально выбирается |
| Бюджет | Обычный потолок цены: медиана его выборов + запас 20% |
| С кем | Охотнее с друзьями, один или через «ищу компанию» (множитель «если идут друзья», например ×2.4) |
| Погода | В дождь поднимаем события под крышей, в солнце — горы и open-air |
| Похожие люди | Куда пошли люди с похожим вкусом — так находится новое |
| Формат | Камерно / массово, длинные события / разовые |

Удобство дороги учитываем тихо, в порядке карточек. **В самой карточке расстояние не пишем.**

Теги ставит ИИ пайплайна при разборе события (см. `PIPELINE.md`). 10 интересов регистрации — это группы тегов:

| Интерес | Теги (примеры) |
|---|---|
| Живая музыка | джаз, рок, акустика, джем, open-air-концерт |
| Посмеяться | стендап, импров, открытый микрофон |
| Горы и природа | поход, пикник, закат, озеро |
| Бег и вело | забег, велопрогулка, йога в парке |
| Новые люди | нетворкинг, языковой клуб, «можно одному» |
| Настолки | мафия, настолки, квиз |
| Выставки | искусство, фото, аниме, музеи |
| Еда и маркеты | маркет, фудфест, дегустация |
| Вечеринки | вечеринка, диджей, танцы |
| Лекции и кино | лекция, кинопоказ, мастер-класс |

## 3. Как собирается колода

**Оценка карточки** — взвешенная сумма, каждый компонент нормирован в 0..1:

| Компонент | Вес |
|---|---|
| Совпадение со вкусом (теги) | 35% |
| Идут друзья | 20% |
| Удобное время (сетка времени) | 15% |
| Цена в бюджете | 10% |
| Скоро и свежее | 10% |
| Похожим понравилось | 5% |
| Новое для тебя | 5% |

**Правила колоды:**
- **Первые 3 карточки** — самые сильные совпадения: цепляет с первого свайпа.
- **Не больше 2 карточек одной темы подряд.**
- **Каждая 8-я** — что-то новое за пределами вкуса, чтобы вкус не замыкался в одном жанре. Доля новизны регулируется в админке, по умолчанию ~12%.
- **Бесконечность.** После каждого свайпа следующие 3 карточки пересчитываются, дальше догружаем по 10. Когда кандидаты кончаются, расширяем окно дат, потом ослабляем фильтры.
- **Ничья:** при равной оценке «сегодня» выше, чем «через неделю».
- **Исключения:** уже решённые события (пойду, мимо, прошедшие) в колоду не попадают. «Мимо» не прячет событие с карты и из поиска.
- **Причины остаются внутри.** На карточке только факты: кто из друзей идёт, когда, где, сколько стоит.

## 4. Первые дни

**Ответы при регистрации → 10 карточек-калибровка → дальше решают свайпы.**

- Первые 10 карточек нарочно **разные** в пределах стартового вкуса, и каждый свайп на них весит **вдвое больше**.
- Пока своих данных мало, опираемся на похожих людей и на популярное в городе этой недели.
- Через 30–40 свайпов ответы регистрации весят уже 20%, остальное — поведение.
- Поменял интересы в профиле — стартовый вкус пересчитывается.

## 5. Что затягивает — и не бесит

- **Нет дна.** За любой карточкой есть следующая.
- **Сразу умнее.** Свайпнул вправо джаз — через карточку ещё один джем. Человек чувствует, что подборка «слушает», не видя как.
- **Друзья.** «Игорь тоже идёт» поднимает карточку и сразу даёт повод написать.
- **Каждый выбор ощутим.** Карточка улетает в профиль, вкладка подмигивает «+1».
- **Немного сюрприза.** Каждая 8-я карточка — новое.

## 6. Как понять, что работает

| Метрика | Норма |
|---|---|
| Доля «пойду» от показанных | 20–35% |
| Дошли из нажавших «пойду» | **Главная метрика** |
| Вернулись в «Для тебя» | D1, D7 |
| Отмены и «вернуть» | < 5% |

Как читать отклонения:
- меньше 20% «пойду» — промахиваемся со вкусом;
- больше 35% — карточки слишком лёгкие, люди соглашаются и не идут;
- много отмен — проблема в жестах, а не во вкусе.

## Реализация

- **Один модуль `reco` на TypeScript** — чистые функции без зависимостей от UI и БД:
  - `applySignal(taste, signal)`;
  - `scoreEvent(taste, event, context)`;
  - `buildDeck(taste, candidates, history, context)`.

  В демо-режиме он работает на клиенте. С Supabase тот же код крутится в Edge Function `deck` (или SQL для грубого отбора + TS для финального порядка).
- **Покрыть модуль тестами:**
  - правило «не больше 2 одной темы подряд»;
  - каждая 8-я — новая;
  - отмена стирает сигнал;
  - 3 «мимо» подряд проседают тему;
  - холодный старт из ответов регистрации.
- **Хранение:**
  - `taste` — `user_id`, `tags jsonb`, `time_grid jsonb`, `price_ceiling`, `company_pref`, `start_answers jsonb`, `updated_at`;
  - `signals` — `user_id`, `event_id`, `kind`, `weight`, `created_at` (отмена удаляет строку).
- **«Похожие люди»** — после MVP: эмбеддинги вкуса в pgvector и ближайшие соседи.
- **Админка вкуса** (`TasteAdmin`), только для команды:
  - поиск пользователя;
  - стартовые ответы и «уверенность модели»;
  - текущие веса тегов с изменениями, сетка времени;
  - последние сигналы;
  - таблица «следующие карточки» с разложением оценки по компонентам и сработавшим правилом;
  - переключатель новизны, «Пересчитать колоду», «Сбросить вкус».
