# Исправления по голосовым и проверке на телефонах — 12 октября

Изменения готовы в коде. Действующий сервер и установленный APK этой работой не обновлялись: в среде нет доступа к ключам Supabase/Expo. Сначала нужно обновить сервер, затем собрать APK и проверить аппаратные функции на двух телефонах.

[План работы](PLAN.md). Разобраны оба голосовых, пять видео и скриншоты из сообщения. Видео `05-05-55` превышает лимит загрузки инструмента 32 МБ и не было просмотрено.

## Проверки

- TypeScript приложения и worker, ESLint и Knip прошли.
- Jest: **260 тестов, 26 наборов**. Новые регрессии: серии событий, камера на трёх размерах экрана, близость без старых точек, очередь во время отправки, MIME, таймер запроса и поздний старт карты.
- PostgreSQL 16 + PostGIS, отдельная база: все миграции применены; миграция 24 повторно применена. Старые и новые SQL-регрессии проходят с ролью `authenticated`. Проверены 350 сообщений, повтор без дубля, группа с одним другом, награды без повторного начисления, дата посещения, перенос только владельцем, запрет чтения чужих шагов/чатов и исправления адреса посторонним. Тестовые данные откатываются. Сервисы Auth/Storage/Realtime и cron/network в этой базе заменены минимальными схемами; это проверка SQL/RLS, а не инфраструктуры Supabase.
- Chromium: создание группы, отправка сообщения, вложения 320×640, выбор даты и появление плана, рамки/награды/реакция, маршрут с тестовым ответом. Ошибок JavaScript нет. Сценарий сохранён в `scripts/check-phone-feedback.mjs`.
- Expo: web demo и live, JavaScript/Hermes-пакеты Android/iOS в live. Это **не APK/IPA** и не запуск нативного SDK на устройстве. Конфигурация разрешений движения проверена отдельно.
- Общий код функций собран; `notify` прошёл Deno check с import map на ту же версию Supabase из npm (JSR в среде недоступен).

Шаги принимаются от клиента с ограничением и однократным начислением; аппаратная защита от подмены показаний не реализована. Фоновая частота зависит от Android/iOS; принудительная остановка приложения системой/пользователем может прекратить обновления. Время посещения проверяется по общему интервалу события: отдельные ежедневные часы работы нужно сверять с источником, если их нет в структурированных данных. Автобусы остаются оценкой по данным OSM, без живого расписания.

## Как обновить приложение

После переноса этой ветки в GitHub:

1. **Actions → Supabase backend → Run workflow** на этой ветке. Нужен `SUPABASE_ACCESS_TOKEN`; workflow обновляет схему 18–24 и функции. Миграция 24 должна быть применена до установки нового APK.
2. **Actions → Android APK → Run workflow** на той же ветке. Нужен `EXPO_TOKEN`. Preview теперь увеличивает номер сборки. Для пушей нужен FCM v1 в Expo Credentials — [инструкция](../../KEYS.md).
3. Для старых карточек без точек: **Actions → Проверить адреса событий**. Сначала отчёт (`apply=false`), затем сохранение уверенных совпадений (`apply=true`). `all=true` проверяет также существующие точки. Нужен `SUPABASE_SECRET_KEY`. Частные встречи не затрагиваются; сомнительные адреса остаются для ручной проверки.
4. На двух телефонах: разрешить геолокацию/фон/физическую активность; проверить первый запуск и возврат из настроек; 20 смен вкладок; приглашение → чат → назад; сообщение без сети и повтор; фото разных пропорций; голос/кружок с отменой/замком; вход/выход и пуши; шаги; перенос своей встречи у обоих; карту и навигацию во время движения; фон через 3–15 минут.
