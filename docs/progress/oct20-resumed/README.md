# Продолжение после остановки другой сессии — 20 октября

Основа — `main` `54b62e1`, уже содержащее PR №18. Обновление карты и интерфейса объединено с ранее подготовленными исправлениями сети, друзей, очереди сообщений, фото и web-чата. Рабочая ветка для передачи: `codex/oct20-quality-and-frames`.

Закончены шесть рисованных рамок: яблоки Алматы, тюльпаны, Алатау, тёплый закат, звёздная ночь, золотой узор. На карте, в профиле и в выборе используется общий статичный SVG. Мелкие детали опускаются у небольших пинов; постоянных анимаций и blur нет. Для каждой рамки доступен крупный предпросмотр, в том числе до открытия по уровню. Прежние четыре id сохранены в классической коллекции. Демо-выбор сохраняется на устройстве; live-выбор подтверждается сервером перед обновлением.

Исправлены конфликты объединения: web-чат остаётся прямым, история учитывает высоту плавающего ввода; справочные места и DEM не потеряны. В стиле остался один слой объёмных зданий, экономный 2D-режим не запрашивает DEM. Сохранены повтор загрузки карты и атрибуция по умолчанию.

## Экраны одной сборки

Все изображения ниже получены из одного web-экспорта с `EXPO_PUBLIC_DATA_MODE=demo`. Сеть к внешним сервисам в прогоне заблокирована, поэтому карта показывает предусмотренную подложку и состояние повтора. Это проверка интерфейса; импорт в рабочий Supabase, нативная плавность и фактический рельеф на телефоне здесь не подтверждены. Заставка пропускается перед снимками; переходы предпросмотра дожидаются завершения.

После уточнения владельца исправлена индикация подложки: показано «Показана схема · 3D недоступно · Повторить», переключатель 2D/3D скрыт до загрузки настоящей карты. Браузерная проверка дополнена этим сценарием. На работающей карте подпись «2D» означает действие перехода из 3D в плоский вид. Отсутствие гор на тестовом скриншоте с заблокированной сетью не подтверждает сбой рельефа в APK.

## Проверки и сервер

`npm run typecheck`, `npm run lint`, `npm run knip`, Jest, `npm run test:sql`, `npm run test:db`, web-экспорты demo/live и проверка сборки общего кода Edge Functions. Числа финального прогона сохраняются в `checks.json`. Браузер проверяет сохранение выбранной рамки после reload, её использование в профиле, просмотр шести рисунков, блокировку закрытой рамки, доступность старых вариантов и ширину 320 px: [browser-checks.json](browser-checks.json). Дополнительные сценарии чата, вложений, даты, стикеров, маршрута и исчерпания ленты — в `../oct20-resumed-smoke/`.

Для рабочей базы нужна новая [миграция 29](../../../supabase/migrations/20261020000029_illustrated_frames.sql) после установленной 27. Она расширяет допустимые id и проверяет уровень при INSERT/UPDATE. Миграция надёжности — [20261020000024_reliability.sql](../../../supabase/migrations/20261020000024_reliability.sql). Оба новых файла проверены локально, в рабочую базу этой сессией не применялись. Задача для ИИ с доступом к серверу обновлена в [BACKEND-PROMPT](../../BACKEND-PROMPT-2026-10-20.md). При отсутствии серверной поддержки новая коллекция сообщает о недоступности и сохраняет прежний выбор.

## APK

Профиль `preview` собирает установочный APK с настоящей базой (`live`); новый модуль обработки фото требует новой нативной сборки. В workflow `Android APK` добавлены SQL-проверки. Удалён устаревший шаг, который пытался открыть PR от другой ветки с описанием старого обновления. Сборка запускается публикацией метки `apk-review-*`; результат и URL пишутся в `docs/builds/<метка>.json` на ветке `build-results/<метка>`. Фактический запуск и результат фиксируются отдельно после публикации.

Первый отчёт — `in_progress / checks`; это запуск workflow, готового APK на момент фиксации ещё нет. [Обновляемый результат](https://github.com/Ponchuchu/ryadom/blob/build-results/apk-review-20261020-quality-frames/docs/builds/apk-review-20261020-quality-frames.json) содержит окончательный статус и URL при успешной сборке.
