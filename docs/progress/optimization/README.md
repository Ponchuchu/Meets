# Оптимизация после APK45

Продолжение `af32393`. Все советы трёх роликов проверены по применимости: [VIDEO-AUDIT.md](VIDEO-AUDIT.md). Изменения не ограничиваются дизайном.

## Измеренный результат

Один и тот же синтетический сценарий: **500 чатов, 10 000 локальных отправленных сообщений**, Chromium, 390×844, CPU ×1, сеть к внешним сервисам заблокирована. До — существующий web export af32393; после — виртуализация, индекс сообщений и разделение web-модулей. Значения одного сравнительного прогона, не гарантированное время на телефоне.

| Метрика | До | После |
|---|---:|---:|
| Появление первой строки | 11 555 мс | 2 885 мс |
| Смонтированные строки из 500 | 500 | 32 |
| DOM-элементы всей страницы | 20 796 | 1 519 |
| Сумма длинных задач при загрузке | 10 620 мс | 1 001 мс |
| Ошибки страницы | 0 | 0 |
| Главный web JS-модуль | 7 524 КиБ | 1 066 КиБ |
| Весь web JS, включая отложенные части | 8 525 КиБ | 8 530 КиБ |

Результаты: [before/chats.json](before/chats.json), [after/chats.json](after/chats.json). Главный модуль уменьшился благодаря production async routes только на web. Остальные части загружаются при необходимости; это **не** утверждение, что вся первая страница скачивает ровно 1 МБ. Общий размер кода почти не изменился. Повторные проверочные запуски после изменений дали 2,0–3,1 с до контента и 16–32 смонтированные строки: число зависит от момента пакетной дорисовки FlatList.

Есть разведочные CPU ×6 прогоны карты/рекомендаций: [before/perf.json](before/perf.json), [after/perf.json](after/perf.json). До использовалась параллельная нагрузка, поэтому FPS этих двух прогонов не являются контролируемым сравнением. Даже по времени оболочки карты устойчивого выигрыша нет (8,5 с → 9,9 с). Эти цифры **не** Android FPS: WebGL программный, внешние тайлы заблокированы. Для утверждений о скорости карты на телефоне нужен новый APK и нативный trace.

## Изменения

- **Карта:** прекращена упреждающая загрузка полных профилей всех друзей. Для обычных live-точек хватает результата серверной приватности. Подробности выбранного друга используют общий кэш `person` со страницей профиля/чатом. Для N друзей устранено до 4×N запросов при открытии карты без выбора человека; это оценка по коду, не production-сетевая трасса.
- **Карта вне фокуса:** выключаются polling хвоста друга/пробок/погоды и интерполяция координат. При возврате показываются текущие координаты. Поиск текущего положения друга в массиве сглаживания заменён индексом Map.
- **Чаты:** FlatList с начальной порцией 8 и окном 5. Превью локальных сообщений индексируются один раз по chatId: вместо двух полных обходов 10 000 сообщений для каждого из 500 чатов — один проход и чтение индекса. Данные событий/людей для строк тоже индексируются.
- **Вложения:** до 512 подписанных ссылок в памяти, 55 минут при серверной подписи 60 минут. Только недостающие пути отправляются на подпись; одинаковые одновременные запросы объединяются. Ошибку можно повторить; выход/удаление аккаунта очищает кэш, поздний ответ прежнего аккаунта не засоряет кэш нового.
- **События:** адреса приватных встреч и сведения об участниках загружаются параллельно после базового списка, без последовательной задержки статистики адресами.
- **Медиа:** стандартный нативный видеокэш Expo (1 ГБ) настраивается на 64 МиБ до создания плееров; при отказе ОС запуск не блокируется. Экономный режим убирает дополнительный blur-слой общей обложки события.
- **Web:** поддерживаемое разделение маршрутов Expo Router, Android/iOS остаются в прежнем поддерживаемом режиме.

Домен сохранён только в черновике revision=2. Нет результатов анализа production-карточек, журналов, EXPLAIN или тарифов Storage. Никакие ключи не запрашивались и не выводились.
