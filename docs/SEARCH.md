# Поиск событий: как это работает и все сценарии

Обновлено 11 октября. Код — в `worker/src/`. Запуск — GitHub → Actions → **search** (афиши и Kimi) и **worker** (Telegram).

## 1. Откуда берутся события

| Источник | Как читается | Что даёт | Токены ИИ |
|---|---|---|---|
| **Яндекс Афиша · Алматы** (`yandex.ts`) | разделы афиши → страница события: разметка + встроенные данные | название, **каждый сеанс** с местным временем, площадка, адрес, **координаты**, цена билетов, фото | 0 |
| **Sxodim** (`sites.ts`) | афиша, 10 страниц → страница события: разметка schema.org | название, дата и время, площадка (отделяется от адреса), адрес, цена, фото | 0 |
| **Telegram** `@afisha_almaty` (`telegram.ts`, `ai.ts`) | публичная страница канала → посты | текст и фото поста; поля разбирает ИИ | на каждый подозрительный пост |
| **Kimi-поиск** (`search.ts`, вход `sources=ai/all`) | веб-поиск Kimi по списку сайтов | дополнительные события, которых нет на афишах | много, лимит аккаунта 3 запроса/мин |

По умолчанию поиск идёт только по афишам (`sources=sites`): быстро (около минуты), точно, бесплатно.

## 2. Путь события

```
найдено → [отсев] → склейка дублей → координаты → фото → «Согласование» (черновик) → одобрение → карта
```

Отсев (событие не доходит до модератора):
- **прошло** — закончилось раньше, чем «сейчас − 3 часа» (идущая выставка остаётся);
- **не Алматы** — площадка дальше 60 км от центра или другой город в тексте (Яндекс: фестиваль в Абу-Даби отбрасывается);
- **реклама / мем** — Telegram, см. п. 6;
- **нет даты** — нечего показывать;
- **дубль** — то же событие уже есть в базе (тот же день, похожее название, та же площадка);
- **тур «на весь год»** — начался давно и не выставка.

Сами сайты ничего не публикуют: всё идёт **черновиком** в «Согласование». Автопубликация возможна только у проверенных источников с уверенностью ≥ 0.9.

## 3. Просроченное

- При приёме: событие, которое уже закончилось, отбрасывается.
- При каждом запуске: **удаляются все черновики, которые уже закончились** (`purgeExpiredDrafts`). Опубликованные и архив не трогаем.

## 4. Дубли между сайтами

Одно событие на Яндексе и на Sxodim — **одна карточка**. Условия: тот же день, та же площадка, похожее название **или** то же время (±30 минут) и ≥ 2 общих корня слов («Миша Лузин» ≈ «Концерт Миши Лузина»). Пустые поля первой карточки (фото, цена, координаты) заполняются со второй, источник записывается как «Яндекс Афиша + Sxodim», уверенность +0.05.
У события с несколькими сеансами каждый сеанс — отдельная карточка (до 4 ближайших).

## 5. Фото — цепочка

1. Фото со страницы события (`og:image`, разметка). Логотипы, иконки и заглушки отбрасываются, адрес проверяется (открывается, это картинка).
2. Фото со **второго сайта**, если событие нашлось на обоих (склейка).
3. Фото из поста Telegram.
4. **Kimi ищет страницу события** (`find_images=N` в запуске, по умолчанию 0): Kimi даёт ссылку на официальную страницу, картинку берёт и проверяет **код** (открывается, не логотип, на странице есть слова из названия). Прямым ссылкам на картинки от ИИ не верим. Стоит токенов, поэтому по умолчанию выключено и ограничено числом карточек.
5. Ничего не нашлось — в приложении показывается **обложка раздела** (стандартная для категории).

Не делаем: генерацию картинок ИИ (Kimi их не рисует, Gemini платный). Если обложки разделов покажутся скучными — отдельный этап.

## 6. Telegram: реклама или событие

1. **Явная реклама без даты** («промокод», «скидка», «розыгрыш», «подпишись»…) отсеивается **без ИИ** (`obviousAd`): токены и лимит не тратятся.
2. Остальное разбирает ИИ (Claude, если есть ключ; иначе Kimi): класс `event / ad / meme / not_almaty / cancel` и поля карточки.
3. ИИ недоступен — запасные **эвристики**; их уверенность < 0.9, поэтому такие черновики всегда идут модератору.
4. Сомнительное (`unclear`, уверенность низкая, нет даты) — не публикуется само.
5. «Отмена/перенос» ищет событие по названию и помечает его на проверку.

Что видно в логе запуска: сколько постов, событий, рекламы, мемов, не-Алматы, дублей, отмен (`summary`).

## 7. Координаты — цепочка

1. Своя таблица площадок `venues` (по названию и алиасам) — уже с точкой.
2. Координаты из Яндекса (`geo` площадки), если событие оттуда.
3. **OpenStreetMap**: запрос «дом + улица» отдельным полем (адрес предварительно чистится: «ул.», «к.», этажи, опечатки).
4. OpenStreetMap по названию площадки.
5. **Mapbox** (токен из `config/public-keys.json`) — только уверенные совпадения (`exact/high/medium`): у него на алматинских адресах часто «low» = промах.
6. Ничего не нашлось — флаг `needs_pin`: точку ставит модератор.
Точка дальше 18 км от центра считается промахом.

## 8. Kimi: когда включать

Аккаунт на бесплатном уровне: 3 запроса в минуту, один одновременно. Код держит паузу 21 с между запросами и повторяет при 429. Если пополнить баланс на платформе Moonshot, задайте `KIMI_MIN_GAP_MS=0` — станет быстрее.
- Основная модель — `kimi-k2.6` (режим размышления выключен, `temperature` не передаём — модели принимают только 1).
- Как дополнение к афишам: `sources=all`; фото: `find_images=6`.
- Секрет GitHub называется `KIMI` (или `KIMI_API_KEY`).

## 9. Что полезно показать в панели разработчика

Воронка запуска (числа уже есть в логе, их можно вынести на экран):
`найдено → прошло / не Алматы / реклама / дубль → черновиков` и по каждому черновику — **откуда фото** (страница / второй сайт / Kimi / нет) и **откуда точка** (площадка в базе / Яндекс / OSM / Mapbox / нет). Кнопки: «Искать сейчас» (сайты), «Дополнить Kimi» (`all`), «Найти фото» (`find_images`).

## 10. Не сделано

- Касир, Ticketon (закрыт для роботов), Кино.kz — не подключены.
- Расписания нет: запуск вручную или из панели.
- Kimi без пополнения баланса даёт мало событий; основа — афиши.
