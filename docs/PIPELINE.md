# Как события попадают на карту

Картинки: `design/png/Pipeline.png`, `design/png/Admin.png`. Скрипт и ИИ делают черновую работу, человек из команды только решает: публиковать или нет.

## 1. Источники (команда добавляет один раз)

- **Источник** — ссылка на раздел города, аккаунт или канал. Примеры из макета: Яндекс Афиша · Алматы, Threads @almaty.weekend, Telegram @afisha_almaty.
- **Уровень доверия.** У каждого источника он свой. Официальным афишам можно разрешить публикацию без проверки при уверенности ИИ 95%+.
- **Юридические ограничения** и что реально доступно — в `TECH.md`, раздел «Источники». Для MVP:
  - стартовый набор из 33 настоящих событий на октябрь 2026 — `data/seed/events-almaty.json`, собран вручную из открытых афиш со ссылками на источники;
  - события, добавленные вручную;
  - «Предложить событие» от пользователей;
  - публичные превью Telegram-каналов.

## 2. Сбор по расписанию

- Каждые 2 часа с 08:00 до полуночи по Алматы.
- Берём только новое с прошлого запуска. Хранится курсор на источник.
- Картинки-афиши тоже: текст с них прочитает ИИ.
- Сырые посты сохраняем в `raw_posts` с источником, ссылкой, текстом, картинками и временем.

## 3. ИИ отличает событие от мусора

Классы: **событие · реклама · мемы/личное · не Алматы · дубль**.

- Реклама и мемы сразу в корзину, модератор их не видит.
- Дубли склеиваются: одно событие из трёх каналов = одна точка. Сравниваем название, дату, площадку и похожесть текста.

## 4. ИИ и геокодер собирают черновик карточки

Поля черновика (structured output):

```json
{
  "is_event": true,
  "title": "Аниме-выставка «Токио в Алматы»",
  "category": "art",
  "tags": ["аниме", "выставка", "для всех"],
  "starts_at": "2026-10-03T11:00:00+05:00",
  "ends_at": "2026-10-04T21:00:00+05:00",
  "is_long": true,
  "venue_name": "ТРЦ …",
  "address": "…",
  "address_note": "3 этаж",
  "price_min": 2500,
  "price_max": null,
  "is_free": false,
  "about": "2–4 предложения по единому образцу: что будет, для кого, что взять, сложность/длительность для походов",
  "organizer": "…",
  "source_url": "…",
  "confidence": 0.94,
  "needs_pin": false
}
```

- **Описание** ИИ пишет по одному образцу для всех типов событий. Никаких «особых блоков».
- **Место.** Сначала ищем в своей таблице `venues` (площадки с алиасами: «ТРЦ Mega», «Мега Алма-Ата»). Не нашли — геокодер предлагает точку.
- **Размытый адрес** («в парке Горького») — карточка помечается `needs_pin`, модератор ставит точку сам.
- **Обложка:** картинка из афиши, если можно использовать. Иначе цветная обложка по категории.
- **Цена.** Мелкий шрифт на афише — флаг «проверь сумму».

## 5. Модерация в админке

Макет `Admin`. Нужен веб-маршрут `/admin`, только для ролей команды.

- **Очередь карточек:** источник, уверенность ИИ, время, название, мета, флаги («поставь точку», «проверь цену»). Кнопки «Опубликовать», «Править», «Нет».
- **Счётчики:** ждут, на карте, отсеял ИИ.
- **Настройка** «Публиковать сразу, если 95%+» — только для источников с доверием.
- **Пуш команде:** «7 событий ждут проверки».
- **Предложения пользователей** («Предложить событие») идут в ту же очередь.
- **Вкладки админки:** Модерация / Рекомендации (`TasteAdmin`) / Источники.

## 6. Жизнь точки на карте

Автоматика по времени: анонс → сегодня → скоро (за 1 ч) → идёт сейчас → скрыто. Подробности и правила длинных событий — `PRODUCT.md`, раздел 3.

- **Отмену** ловит тот же сборщик и пишет всем, кто собирался.
- **После конца** — в архив и в хронику профиля тех, кто отметился «Я на месте».

## Поиск ИИ раз в сутки

- **Зачем:** находит то, чего нет в подключённых каналах, — события у площадок, организаторов, в городских обзорах, бесплатные уличные акции.
- **Как:** `.github/workflows/search.yml`, 08:40 по Алматы. `worker/src/search.ts`: Gemini API с поиском Google — 6 разделов параллельно, короткое задание, ответ только JSON, мало «размышлений» (экономия токенов). Затем наш код без ИИ параллельно открывает страницы: выкидывает битые и чужие ссылки, берёт дату из разметки schema.org и картинку og:image. Ключей базы этот шаг не видит.
- **Карточка:** название, дата, адрес, цена, описание своими словами, ссылка на страницу события. Картинка — с этой страницы (og:image); нет картинки — в приложении обложка раздела. Картинки не генерируем: это реальные события, сгенерированная афиша вводит в заблуждение.
- **Дальше — тот же конвейер:** дубли со всеми источниками, поиск места на карте, флаги. Источник без доверия: всё только в «Согласование».
- **Демо без ключей:** `npm run worker:search-demo`.

## Реализация

- **Сборщик — отдельный воркер на Node/TypeScript** в папке `worker/`. Edge Functions Supabase не подходят: лимит времени работы.
- **Запуск** — GitHub Actions по расписанию: cron `0 3-19/2 * * *` (UTC). Это каждые 2 часа с 08:00 до 00:00 по Алматы.
- **Ключи** — в секретах репозитория: `ANTHROPIC_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
- **ИИ:**
  - Claude Haiku 4.5 классифицирует и извлекает поля (structured outputs, картинки — vision);
  - при `confidence < 0.8` — повтор на Claude Sonnet 5.
- **Демо-режим:** воркер умеет работать на папке с примерами постов (`worker/fixtures/`) и печатать черновики без записи в БД.

## Адреса, цены, состав, фото (26 октября)

- **Единый вид адреса:** «улица Жандосова, 1/1», «проспект Абая, 120» — тип улицы полным словом впереди, без города; этаж и офис — в `address_note`.
  Сборщик приводит адрес так: `canonAddress` в `worker/src/ruAddress.ts`. База для уже сохранённых адресов делает то же: `public.addr_ru`, миграция 44.
- **Справочник адресов** (`public.addresses`): у каждой улицы одно русское название (`street_map`). Казахская улица получает имя русской с той же основой поблизости, а если такой нет — правила перевода («Нұрпейісов көшесі» → «улица Нурпейисова»). Дома, которые были только по-казахски («Абай даңғылы, 120»), теперь находятся и по-русски. Исходное написание лежит в `street_src`.
- **ИИ-редактор** (`polish.ts`, Kimi, пачками по 8) кроме описания возвращает:
  - кто выступает (`performers`);
  - бесплатно ли (`free`) и цену (`price`) — по смыслу текста;
  - адрес в едином виде.

  Цена и «бесплатно» со страницы афиши важнее догадки ИИ. Адрес от ИИ берётся только вместо пустого или размытого; точку всё равно ищет справочник.
- **Состав из интернета** (`lineup.ts`): у концерта, стендапа, спектакля, вечеринки или лекции без имён Kimi ищет страницу события. Имя попадает в карточку, только если оно написано на этой странице; потом редактор переписывает описание с составом. Лимит — `LINEUP_LOOKUPS`, по умолчанию 6 карточек за запуск.
- **Фото из интернета** для карточек без картинки теперь включено по умолчанию: до 6 за поиск (`find_images`).
